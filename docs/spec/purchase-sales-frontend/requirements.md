# 仕入・売上管理フロントエンド 要件定義

## 背景

fasse_infra で構築した REST API を利用し、Flutter から仕入・売上管理のデータを操作するフロントエンドを提供する。

## 目的

- 仕入・売上・マスタデータを画面から閲覧・登録・更新・削除できるようにする
- API のベース URL を環境ごとに切り替えられるようにする
- 将来的な Spring Boot への移行を見据えた API 抽象化を行う

## スコープ

- マスタデータ画面: 品目・仕入先・メニュー・消費税率
- 伝票画面: 仕入伝票・売上伝票
- API 接続設定: stg / prod 用の基底 URL 管理
- エラー表示とローディング状態
- 初期画面の主要機能選択 UI

## 画面仕様

- Flutter 起動時の初期画面では、3つの主要ボタンを縦方向に並べて表示する
- 表示順は上から「仕入伝票」「売上伝票」「マスタメンテナンス」とする
- 「マスタメンテナンス」ボタン押下時に、さらに 4 つのマスタ操作ボタンを縦方向に表示する
- 表示順は上から「品目」「仕入先」「メニュー」「消費税率」とする
- 仕入伝票・売上伝票・各マスタの画面では、対象 domain のデータ一覧を表示し、追加・変更・削除ができるようにする
- WebAPI で実装済みの各機能は、Flutter 側からすべて利用できるようにする
- 画面サイズが小さい場合でも操作しやすいよう、余白・ボタンサイズ・スクロール対応を適切に行う

## 消費税対応

- 品目マスタ・メニューマスタの登録・変更画面では、税区分（標準税率／軽減税率／非課税）を選択できるようにする
- 品目・メニューの単価、および伝票明細の単価は税抜金額として扱う（飲食店の売上は持ち帰り（軽減税率）とイートイン（標準税率）が混在するため、税込の単一価格では表現できない）
- 消費税率マスタ画面では、税区分（標準／軽減／非課税）ごとに税率・適用開始日・適用終了日を登録・変更・削除できるようにする。非課税区分も他の区分と同様に消費税率マスタで管理し、クライアント側で税率0を独自に決め打ちすることはしない
- 仕入伝票・売上伝票の明細行では、選択した品目/メニューの税区分と、伝票の基準日（仕入伝票: 仕入日、売上伝票: 営業日）に基づき、その時点で有効な税率を自動的にセットする（ユーザーが税率を手入力することはない）
- 基準日時点で有効な税率が消費税率マスタに存在しない場合は、登録前にエラーメッセージを表示し、登録をブロックする
- 品目・メニューの税区分を登録後に変更しても、既存の伝票明細には影響しない（明細の税率は登録時点の値をスナップショットとして保持するため）
- 消費税額の計算は、明細ごとに税率を掛けた値を都度端数処理せず、税率ごとに集計してから1回だけ端数処理を行う（インボイス制度（適格請求書等保存方式）の要件に基づく）。端数処理の方法は切り捨てとする

## 伝票・マスタの入力仕様

- 仕入伝票・売上伝票の一覧画面は、初期表示時点で直近7日分（7日前〜当日）のデータを表示する。表示期間はカレンダーUIで変更できる
- 売上伝票の支払方法（`payment_method`）は、フロント側で固定リスト（現金／クレジット／電子マネー）から選択する形式とする（自由入力にしない）
- 売上伝票フォームには値引き額（`discount_amount`）の入力欄を設ける
- 仕入伝票・売上伝票の明細行で品目/メニューを選択する際、論理削除済み（`is_active=false`）のものは新規選択肢から除外する
- ただし、既に登録済みの明細が参照している品目/メニューが後から論理削除された場合、その明細の編集画面では選択済みの品目/メニューを引き続き表示する（名称に「(取扱終了)」等を付与する）。一覧・詳細（閲覧専用）画面でも、論理削除済みの品目/メニューの名称を通常通り表示する
- 各フォームの必須項目チェックはクライアント側で実装する（バックエンドAPIは必須項目の検証を行わず、未入力のまま送信されたリクエストもそのまま登録してしまうため）
- 仕入伝票・売上伝票はヘッダと明細をまとめて1つの登録・編集画面で入力する（APIがヘッダ+明細を1リクエストで受け取る仕様のため、ヘッダのみを先に登録する画面遷移は用意しない）。「明細行を追加」操作は画面内で行を追加するのみで、その時点ではAPIを呼び出さない。画面下部の「登録」（編集時は「更新」）ボタン押下時に、ヘッダと全明細行をまとめて1回のリクエストとして送信する

## スコープ外

- 認証・認可
- 複雑な集計・レポート画面
- オフライン同期

## 受け入れ条件

- API のベース URL を環境変数で切り替えられる
- 一覧・詳細・登録・更新・削除の基本フローが動作する
- API エラー時にユーザーへ分かりやすいメッセージを表示できる
- 初期画面で 3 つの主要ボタンが縦に並ぶ
- マスタメンテナンスから 4 つのマスタボタン（品目・仕入先・メニュー・消費税率）が縦に並ぶ
- 左上の戻るボタンで直前の画面へ戻れる
- 品目・メニューの登録・変更画面で税区分（標準／軽減／非課税）を選択できる
- 消費税率マスタの一覧・登録・変更・削除ができる
- 仕入伝票・売上伝票の明細行で、税区分と伝票の基準日から税率が自動セットされ、手入力を必要としない
- 基準日時点で有効な税率が存在しない場合、登録前にエラーが表示される
- 仕入伝票・売上伝票の一覧画面が直近7日分をデフォルト表示し、カレンダーで期間を変更できる
- 売上伝票の支払方法が固定リスト（現金／クレジット／電子マネー）から選択できる
- 売上伝票に値引き額を入力できる
- 論理削除済みの品目/メニューが新規明細の選択肢に表示されない。既存明細で参照されている場合は編集画面・一覧・詳細で引き続き表示される
- 各フォームで必須項目が未入力の場合、送信前にクライアント側でエラーが表示される
- 仕入伝票・売上伝票の登録・編集画面で、明細行を画面内で追加・削除でき、「登録」／「更新」ボタン押下時にヘッダと明細がまとめて1回のリクエストで送信される
- 仕様書と実装が対応づけられている
